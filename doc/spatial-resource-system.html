1. Design Philosophy 设计哲学

Items are passive · 物品是被动的

物品不知道谁持有自己。只知道自己在哪、有多少、能被多远处看到。没有 owner 属性、没有 transfer() 方法、没有 belongs_to 字段。

NPCs are active · NPC 是主动的

NPC 决定移动什么。Geralt 把金币从口袋拿到手上。Rachel 从 Geralt 手上拿走金币。引擎不判断"交易"——引擎只看到两次独立的 move()。

Constraints are physical laws · 约束是物理定律

约束校验物理可行性：位置上有足够的数量吗？物品耐久够吗？冷却好了吗？约束不判断"这个交易合理吗"。只判断"能做成吗"。

Ownership is LLM inference · 归属是 LLM 推断

引擎不记录"金币属于 Geralt"。引擎只报告金币在 Geralt 口袋里（radius=0）。LLM 自己从感官信息中推断归属。

2. System Architecture 系统架构

3. The Spatial Object Interface 空间物体接口

一切物体——金币、苹果、剑、门——实现同一接口。唯一的区别是 Class Singleton（可互换物）用一个共享注册表，Entity（唯一物）用自身位置属性。

move(from, to, qty, radius)

从位置 A 移动数量到位置 B，设置新半径。商品不知道谁在移动它。

qty_at(pos) → int

该位置有多少。面向 Object 查询——不区分 gold 还是 sword。

radius_at(pos) → int

该位置堆叠的当前可见半径。0 = pocket (不可见), 1 = hand (近处), 5 = ground (远处)。

all_near(center, radius) → list

中心点半径内的所有堆叠——供感官系统查询。引擎通过此接口渲染感官文本。

关键洞察: move() 不是 transfer()。没有 sender 和 receiver。只有 from 和 to 两个位置坐标。NPC 调用 move(hand, hand, 5, 1) — 引擎不知道 former 是谁的 hand、latter 是谁的 hand。物理即转移。归属即位置。

4. Constraint System 约束系统

每个约束是一个自包含的物理定律。引擎分组循环——不知道自己执行的是什么约束。

activation() — 我该上班吗？

约束检查双方都在 action 里声明了自己。单方声明 → 不激活。双方都声明 → 激活。

timing — 我在哪个阶段工作？

pre: 执行前校验。数量够吗？
exec: 执行中操作。扣减耐久。
post: 执行后记录。记日志。

validate() — 物理可行吗？

返回 (bool, reason)。不通过 → 引擎停止，不执行 apply。LLM 下轮感知失败原因。

apply() — 执行操作

只在 validate 通过后调用。无状态残留——一次完成。

4.1 Engine Dispatch Loop 引擎派发循环

def process(entities, action_def, world):
    active = [c for c in ALL if c.activation(entities, action_def)]

    for group in ["pre", "exec", "post"]:
        for c in group_by(active, group):
            ok, reason = c.validate(entities, action_def, world)
            if not ok:
                return Result(failed=c, reason=reason)
            c.apply(entities, action_def, world)
    return Result(ok=True)

# 引擎不知道任何约束名、不知道 gold 是什么、不知道什么是 "consent"
# 只知道: 拿一组 constraint 实例，按 timing 分组，循环调 validate + apply



  新增约束: 三步——写一个 25 行的 class + @register("name") 装饰器 + YAML 里声明 constraints: ["name"]。引擎零改动。约束自己决定 timing、activation、如何 validate。





5. Concrete Scenario: Gold Changes Hands 具体场景：金币易手



Geralt 有 50 金币在口袋。Rachel 有 3 金币在口袋。Geralt 决定给 Rachel 5 金币。










  核心洞察: 整个流程不存在 transfer(from_entity, to_entity)。只存在 move(from_pos, to_pos)。物品不知道"谁在给谁"——只知道位置和半径变了。归属是 LLM 从 $sensory$ 推断的心智模型——不是引擎维护的数据结构。
