1. The Unification 统一：qty 是唯一开关

qty = 1 (唯一物)

IronSword · OakDoor · PoisonTrap。每个 entity 只有一个——move 就是改 entity.pos。

qty > 1 (可互换物)

GoldCoin · Apple · Potion。每个 entity 有一堆——move 是两个 entity 的 qty 加减。归零时 entity 消失。

零新概念

不需要 SpatialObject ABC。不需要 ClassSingleton。不需要 SpatialProxy。所有物品已是 Entity + private_attrs + layers。

零新文件

不建新模块。entity.py 加 split/merge。interaction.py 加约束 dispatch。sensory.py 已支持——entity 遍历不变。AppleCrate 的这个模式已经被证明了。

苹果箱已经是这个模式。 private_attrs.apple_count: 10。只是缺少移动语义和约束。把 qty 从语义扩展为物理——不建新概念——是从现有结构扩展的。

AppleCrate already uses this pattern. private_attrs.apple_count: 10. Just missing movement + constraints. Qty expanded from semantic to physical — no new concepts — extension of existing structure.

2. Entity with qty — How It Works 带 qty 的 Entity——如何工作

2.1 YAML 声明 —— 和 AppleCrate 完全一样

# 唯一物 — qty=1 隐式
- id: iron_sword
  zone: bar_zone
  pos: [10, 15]
  interaction:
    private_attrs:
      durability: 100
      radius: 1               # visible in hand

# 可互换物 — qty=50
- id: gold_geralt_pocket
  zone: bar_zone
  pos: [12, 7]               # 在 Geralt 的口袋位置
  interaction:
    private_attrs:
      qty: 50                    # ← 这就是区别。就这么一个字段。
      radius: -1              # invisible — only self sees pocket
  visual:
    properties:
      look: "golden coins"
为什么优雅：世界上的每个物体都是一个 entity。qty=1 → 唯一。qty=50 → 可互换。不需要注册表、不需要 singleton、不需要 proxy。AppleCrate 已经是 private_attrs.apple_count: 10——只是缺乏移动语义。把它从"数字属性"变成"物理属性"——就是全部的工作。

Why this is elegant: Every object in the world is an entity. qty=1 = unique. qty=50 = fungible. No registry, no singleton, no proxy. AppleCrate already has private_attrs.apple_count: 10 — it's just missing movement semantics. Turn it from a "numeric property" into a "physical property" — that's the entire job.

2.2 Entity 方法 —— 在现有 entity.py 中加

# entity.py — 现有 Entity 类 + 2 个新方法

class Entity:
    # ── 现有字段 (不变) ──
    id: str; name: str; zone: str; pos: list[int]
    layers: dict; private_attrs: dict

    # ── 现有方法 (不变) ──
    def has(self, key): return key in self.layers
    def get(self, key): return self.layers.get(key)
    def distance_to(self, other): return abs(self.pos[0]-other.pos[0]) + abs(self.pos[1]-other.pos[1])
    def move_to(self, target_pos): self.pos = target_pos  # + grid update + carry r=0 items

# ── 新方法: qty 操作 ──

    def has_qty(self) → bool:
        return self.get("interaction").private_attrs.get("qty", 1) > 1
为什么要有: 判断"这是唯一物还是可互换物"。qty=1 的 item 不需要堆叠/拆分——qty>1 的 item 需要。
谁调: interaction.py 执行 move 操作前——决定走"改坐标"还是"改 qty"。
默认值是 1: 没有显式 qty 的 item 就是唯一物——和 AppleCrate 的默认 qty=1 一致。 
    def split(self, qty: int) → "Entity":
        # 从此 entity 分出 qty 个。返回新 entity。
        if not self.has_qty(): return None
        have = self.private_attrs["qty"]
        if have <= qty: return None
        self.private_attrs["qty"] -= qty
        return Entity(..., private_attrs={"qty": qty, ...})
为什么要有: Geralt 从口袋拿出 5 个金币——源 entity 的 qty 从 50 变 45，新 entity 有 qty=5，位置在 hand。
谁调: interaction.py 执行 take_out action 时——split source entity，把新 entity 的 pos 设为 hand。
约束先检查: qty_non_negative 在 split 之前校验 source entity 有足够数量。 
    def merge(self, other: "Entity") → bool:
        # 把 other 的 qty 合入 self。如果 self 没有 qty 或不是同类型 → False。
        if not self.has_qty() or not other.has_qty(): return False
        self.private_attrs["qty"] += other.private_attrs["qty"]
        other.private_attrs["qty"] = 0
        return True
为什么要有: Rachel 把金币从手里放进口袋——手上的 entity 和口袋里的 entity 是同类型——合并 qty。手上的 entity 归零→消失。
谁调: interaction.py 执行 put_away action 时——合并手 entity 和口袋 entity。或同位置的两个同类型堆叠自然合并。
归零时: qty 归零的 entity 标记为移除——sensory 系统下轮不会再看到。

3. Constraint System 约束系统

3.1 Constraint ABC

class Constraint(ABC):
    # 所有物理定律基类。30 行。引擎只知 activation + timing + validate + apply。
    timing: str = "pre"

    def activation(self, entities, action_def) → bool: pass
为什么要有: 约束自己决定"这次需要我吗"。不每个约束每次交互都触发。引擎循环所有约束——调 activation()→True 的参与本轮。
qty_non_negative 什么时候激活: "resource" in action_def — 涉及资源操作才需要数量校验。talk 不需要。
引擎不知道激活条件——每个约束自己决定。 
    def validate(self, entities, action_def, world) → (bool, str): pass
为什么要有: 校验物理可行性。返回 (通过, 失败原因)。引擎按 timing 分组——每个组内逐个 validate——任一失败→停止。
失败后: 引擎返回 failed=constraint_name + reason。LLM 下轮从感官通道感知失败——自己决定换策略。 
    def apply(self, entities, action_def, world): pass
为什么要有: 只在 validate 通过后调用。原子操作——无状态残留。
门控约束: qty_non_negative — pass（只校验不执行——split 由 entity 执行）。
操作约束: consumption — qty-1 + deltas。

3.2 Registry + process()

class ConstraintRegistry:
    _constraints: dict[str, Constraint] = {}

    def process(self, entities, action_def, world):
        active = [c for c in self._constraints.values()
                  if c.activation(entities, action_def)]
        for group in ["pre", "exec", "post"]:
            for c in [c for c in active if c.timing == group]:
                ok, reason = c.validate(entities, action_def, world)
                if not ok: return Result(failed=c.name, reason=reason)
                c.apply(entities, action_def, world)
        return Result(ok=True)
引擎一行调: constraints.process(entities, action_def, world)。不认识约束名、不认识 timing、不认识 gold。只循环 + 分组 + 调 validate + 调 apply。
分组原因: pre 失败→不执行任何 apply。exec 失败→不执行 post。post 不计分——只记录。三个组有序——引擎只循环。

3.3 qty_non_negative — 具体约束

@register("qty_non_negative")
class QtyNonNegativeConstraint(Constraint):
    timing = "pre"

    def activation(self, entities, action_def):
        return "resource" in action_def
为什么查 "resource" 字段: 不是每个交互都涉及资源。talk 不用数量校验。take_out(gold,5) 定义了 resource 和 qty——需要校验。
真触发: take_out / take / give / eat / pick_up — 移动或消耗物品。
不触发: talk / walk / follow / open — 无资源操作。 
    def validate(self, entities, action_def, world):
        source = action_def["source_entity"]       # Entity 对象
        need   = action_def["qty"]
        have   = source.private_attrs.get("qty", 1)
        ok     = have >= need
        reason = f"{source.name}: need {need}, have {have}" if not ok else ""
        return ok, reason
参数 source_entity: 引擎在执行 action 前找到源 entity——Spatial getter——从 find_entity_by_name 返回。
为什么 private_attrs.get("qty", 1): 默认 1 — 唯一物品的 qty 总是 ≥1（entity 存在）。
失败时: 引擎停止。LLM 下轮感官感知状态不变——自己推理"数量不够"。 
    def apply(self, entities, action_def, world):
        pass    # 门控 — split 由 Entity 执行
为什么不执行 split: 物理操作是 entity.split() 的事——不是约束的事。约束只做准入控制。引擎在 process() 返回 ok 后自己调 entity.split()。

4. How Items Appear in Sensory 物品如何进入感官

sensory.py: update()
│
├─ world.get_nearby_ids(zone, pos, view_radius)
│ → 返回附近所有 entity ID — 包括 GoldCoin entity、AppleCrate entity
│
├─ 遍历每个 entity → 迭代 entity.layers
│ ├─ visual layer: observe(d) → {look: "golden coins", qty: 5}
│ └─ → observer.sensory.channels["visual"]["gold_hand"] = SensorRecord(...)
│
├─ to_prompt("visual", cfg)
│ └─ template: "{name} ({distance}格)"
│ └─ → "Gold (0格)"
│
└─ ctx["sensory_text"] → LLM sees "Gold (0格)"
     —— 和 AppleCrate 完全相同的路径。零改动。
r=-1 (口袋/贴身): r < 0 的 entity 仅对自身位置可见。sensory 只需一行过滤：if entity.private_attrs.get("radius",1) < 0 and entity.pos != observer.pos: continue。零特殊情况。私密——仅自己看到。
r=0 (隐藏): 永不可见——如埋在地下的物品。
r=1 (手中): 正常可见——distance ≤ view_radius。
r≥5 (地面): 远处可见——distance ≤ max(radius, view_radius)。

r=-1 (pocket): entities with r < 0 are visible only to the observer at that position. One filter line in sensory: if radius < 0 and entity.pos != observer.pos: continue. Zero special cases. Private — self only.
