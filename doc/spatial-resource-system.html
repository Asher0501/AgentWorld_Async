1. Design Principles 设计原则

① exec_op — 唯一操作入口

NPC 和 Item 的所有操作走同一函数。exec_op(entity, op_name, params, world)。split / merge / apply_delta / speak / remember — 全部统一 dispach。

② 约束绑在具体操作上

entity 声明 ops.split: {constraints: [qty_non_negative]} — 只有 split 触发。apply_delta 绑 attr_bounds。speak 无约束。每个操作独立声明。

③ LLM 不直接修改任何字段

去掉 self_deltas 的直写。LLM 输出 npc_ops: [{op:"apply_delta", attr:"hunger", delta:-10}] — 引擎调 exec_op — 约束先触发。

④ 同一 tick 可执行多个 op

npc_ops + item_ops + dialogue + move — 一条 LLM 决策里并行携带。边走边说 + 同时操作物品。

⑤ 全 Entity 统一

Gold 是 Entity。Sword 是 Entity。Geralt 也是 Entity。所有 entity 都用 ops 声明操作。没有 NPC vs Item 的概念分裂。

⑥ 现有感官管线复用

Entity 通过 visual/interaction layer 暴露给 sensory。r=-1 仅自己可见。零新通道。

2. Entity ops — NPC 和 Item 统一声明 统一实体操作

2.1 YAML — NPC 和 Gold 同结构

# NPC — 和 Item 完全同结构的 ops 声明
- id: geralt
  agent: {autonomous: true, personality: "猎魔人..."}
  interaction:
    private_attrs: {hunger: 40, thirst: 45, social: 56, energy: 65, fun: 36, mood: 45}
    ops:
      apply_delta: {constraints: ["attr_bounds"]}   ← 属性增减需要边界校验
      speak:       {constraints: []}                  ← 说话无约束
      remember:    {constraints: []}                  ← 记忆无约束
      move_to:     {constraints: []}                  ← 移动无约束 (未来: energy_cost)

# Gold Item — 同结构, 不同的 ops
- id: gold_geralt_pocket
  zone: bar_zone  pos: [12, 7]
  interaction:
    private_attrs: {qty: 50, radius: -1}
    ops:
      split:    {constraints: ["qty_non_negative"]}
      merge:    {constraints: []}
      read_qty: {}
      move_to:  {constraints: []}
NPC 和 Item — ops 结构完全一致。 唯一的区别是 ops 的语义。NPC 有 apply_delta / speak / remember。Item 有 split / merge / read_qty。引擎不区分 —— 都是 exec_op(entity, op_name, params, world)。

2.2 exec_op — 唯一入口

def exec_op(entity, op_name, params, world):
    # NPC 和 Item 的所有操作走此入口。引擎一行调用。

    op_def = entity.interaction.ops.get(op_name, {})
    if not op_def: return Result(failed="unknown_op")   # 操作未注册 — 拒绝

    constraints_list = op_def.get("constraints", [])
    for name in constraints_list:                          # 按操作类型读约束列表
        c = REGISTRY[name]
        ok, reason = c.validate(entity, params, world)
        if not ok:
            return Result(failed=name, reason=reason)      # 约束不通过 — 停止
        c.apply(entity, params, world)                    # 约束通过 — 执行

    # 约束全部通过 → 执行操作本身
    if op_name == "apply_delta":
        entity.interaction.apply_deltas({params["attr"]: params["delta"]})
    elif op_name == "split":
        return entity.split(params["qty"])
    elif op_name == "speak":
        entity._write_speech(params["dialogue"])
    elif op_name == "merge":
        return entity.merge(params["other"])
    return Result(ok=True)
引擎做的事: 读 entity.interaction.ops[op_name].constraints → 全部 validate → 全部 apply → 执行操作。不知道 gold 是什么、不知道 hunger 是什么。只知道 "这个 entity 的这个操作声明了这些约束"。

4.2 attr_bounds — 替代硬编码 clamp

@register("attr_bounds")
class AttrBoundsConstraint(Constraint):
    timing = "pre"

    def activation(self, entity, params):
        return params.get("op") == "apply_delta"

    def validate(self, entity, params, world):
        attr  = params["attr"]
        delta = params["delta"]
        cur   = entity.interaction.private_attrs.get(attr, 0)
        new   = cur + delta
        if attr == "coins":  return new >= 0, f"{attr}: {new} < 0"
        return 0 <= new <= 100, f"{attr}: {cur}+{delta}={new} out of [0,100]"
替代 InteractionLayer 的硬编码 clamp。 当前 apply_deltas 里有 max(lo, min(hi, val)) — 这是引擎在"修正" LLM 的输出。改后 — attr_bounds 约束校验 — 不通过 → 拒绝操作 — LLM 下轮感知失败 — 自己调整。

5. Sensory Pipeline + Radius Model 感官管线 + 半径模型

radius语义Sensory 规则
-1口袋 / 贴身 — 仅自己可见r<0 and pos!=observer → skip
0隐藏 — 所有人不可见永不可见
1手中 — 近处可见distance ≤ view_radius
≥5地面 — 远处可见distance ≤ max(r, view_radius)
零新通道。 Entity 通过现有 visual/interaction layer 暴露给 sensory。所有 entity 走同一条管线 — sensory.py 的 entity 遍历不变。r=-1 的 entity 仅 observer.pos == entity.pos 时渲染 — 一行过滤。

6. Full Scenario — Gold Transfer + Talk + Move 完整场景

Tick N — Geralt: 走到铁匠边 + 拿出金币 + 说话 — 同一 tick
│
├─ LLM: { action: "走向铁匠", npc_ops: [{op:"apply_delta", attr:"social", delta:3}], item_ops: [{entity:"gold", op:"split", qty:5}], dialogue: "来了来了，让我看看这个剑", target_name: "矮人铁匠" }
│
├─ 引擎 dispatch — 并行处理所有 ops
│ ├─ exec_op(geralt, "apply_delta", {attr:"social", delta:3})
│ │ └─ attr_bounds.validate → social:56+3=59 in [0,100] → ✓
│ │ └─ geralt.social = 59
│ ├─ exec_op(gold_entity, "split", {qty:5})
│ │ └─ qty_non_negative.validate → gold_entity.qty=50 ≥ 5 → ✓
│ │ └─ gold_entity.split(5) → 源 qty:50→45, 新 entity(qty=5, r=1) 在 hand 位置
│ ├─ exec_op(geralt, "speak", {dialogue:"来了来了"})
│ │ └─ geralt 的 auditory layer 写入 — 周围 agent 下轮感官听到
│ └─ target_name="矮人铁匠" → engine: agent.move_to(target.pos)
│
├─ Tick N+1 — 矮人铁匠感知:
│ └─ sensory: Gold (0格, r=1) — 在 Geralt 手中 + Geralt 身体位置变了
│ └─ conversation: "来了来了，让我看看这个剑"
│ └─ 铁匠 LLM: "他来了！他手里有金币。他可能想买。" → 不再说那句 ×9 的剑胚子
│
└─ 对话重复率下降 — 因为物理位置 + 物品状态自然推进叙事
为什么 ×9 的口头重复应该在这里终结: 铁匠看 Geralt 走过来 + 手上有金币 + 说"让我看看这个剑" — 三个感官信号同时变化 — 铁匠的 LLM 有新的输入可以做新的判断 — 不再走"白狼没来→再喊一次"的死循环。物理状态变化打破对话循环。
