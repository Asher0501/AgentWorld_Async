1. Core Principles 核心原则

① 物品是被动的

物品只知道自己的空间状态——qty_at(x,y)、radius_at(x,y)、move(from,to,qty,r)。没有 owner、没有 transfer、没有 belongs_to。只能被移动——不知道谁在移动它。Items are passive — they don't know who owns them.

② NPC 是主动的

NPC 决定移动什么。参数全是纯坐标。Geralt 把金币从 (12,7) 移到 (12,8)，Rachel 从 (12,8) 移到 (14,9)。引擎不知道"交易"——只知道两次 move()。NPCs decide what to move. All parameters are pure coordinates.

③ 约束即物理

约束校验物理可行性。位置上有足够的数量吗？耐久够吗？冷却好了吗？约束不判断"交易是否公平"。只判断物理可行性。Constraints validate physical feasibility — nothing more.

④ 归属 = LLM 推断

引擎不记录"金币属于 Geralt"。引擎只报告金币在某个坐标。LLM 从 sensory 看到"金币在 Geralt 身旁"——自己推断归属。Ownership is LLM inference — not a data structure.

⑤ 半径即权限

radius=0 → sensory 不可见 → LLM 不知道存在 → 不可能 move。radius=1 → 可见 + interact_radius 控制能否够到。radius≥5 → view_radius 内可见。不需要 access-control 约束。Radius is permission. No extra access-control code.

⑥ 不建新通道

SpatialObject 不是新的 channel——是现有 sensory 系统遍历的数据源之一。现有管线不变：SensorySystem.update → channels → SensorySource → ctx。No new channel. SpatialObject is a data source within the existing sensory pipeline.

4. Constraint System 约束系统

activation() — 触发条件

双方都在 action 的 constraints 列表里声明了此约束 → 激活。单方声明 → 不触发。

timing — 触发时机

pre 执行前校验 · exec 执行中操作 · post 执行后记录

validate() → bool

校验物理可行性。不通过 → 引擎停止。LLM 下轮从感官感知失败原因。

apply()

只在 validate 通过后调用。原子操作——无状态残留。

# 引擎一行调用。Zero domain knowledge.
constraints.process(entities, action_def, world)

# 模块内部 — 按 timing 分组，逐个 validate + apply
def process(entities, action_def, world):
    active = [c for c in ALL if c.activation(entities, action_def)]
    for group in ["pre", "exec", "post"]:
        for c in group_by(active, group):
            ok, reason = c.validate(entities, action_def, world)
            if not ok: return Result(failed=c, reason=reason)
            c.apply(entities, action_def, world)
    return Result(ok=True)
