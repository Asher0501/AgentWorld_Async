1. Overview 概览

Unified Entry Point 统一入口

All entity interactions flow through a single interaction.interact() method. NPC↔NPC dialogue, NPC↔Item usage, resource transfers — dispatched by YAML-defined action type names, not by hardcoded if/elif chains.

所有实体交互走单一入口。NPC↔NPC 对话、NPC↔Item 使用、资源转移——全部由 YAML 定义的 action type 名派发，无硬编码分支。

YAML-Defined Actions YAML 定义动作

Every entity declares its interact capabilities in world.yaml. NPC base provides send, receive, talk, follow. Items provide eat, pick_up, open. Add new actions — zero Python changes.

每个实体在 world.yaml 声明交互能力。NPC 基础提供 send/receive/talk/follow。Item 提供 eat/pick_up/open。加新动作零 Python 改动。

Constraint Auto-Activation 约束自动激活

Each action declares constraints (e.g. conservation, consumption). The engine matches both sides. Only constraints registered by both parties activate. Single-party registration is silently ignored.

每个动作声明约束。引擎匹配双方。只有双方都注册的约束激活。单方注册静默忽略。

Resource Ledger 资源账本

A flat, entity-level balance sheet: gold, mana, apples, potions. Transfers validated against physical law (no creation from void). The engine knows zero domain semantics.

实体级平账本。转移按物理定律校验（不能无中生有）。引擎知道零领域语义。

LLM Sovereignty LLM 主权

The LLM receives available actions and resource state through channels. It decides what to do. The engine validates physical feasibility — not economic wisdom.

LLM 通过 channel 看到可执行动作和资源状态。自己决定做什么。引擎只校验物理可行性——不判断经济合理性。

Closed Loop 闭环

Resources become a 6th sensory channel. The existing action→feedback→decision cycle extends naturally: resource changes perceived in subsequent ticks through the resource channel.

资源成为第6个感官通道。现有 action→feedback→decision 循环自然扩展：资源变化通过 resource channel 在下轮被感知。

2. System Architecture 系统架构

3. Entity YAML Schema 实体 YAML 模式

Every entity declares its interact capabilities and resource state in world.yaml. NPCs inherit base actions; items start from scratch. Specialized entities add new keys. Zero Python.

3.1 NPC Base + Specialization NPC 基础 + 特化

# NPC 基础交互 — 所有 NPC 自动拥有
interact:
  send:    { constraints: ["conservation"] }
  receive: { constraints: ["conservation"] }
  talk:    { }
  follow:  { }

# Geralt — 猎魔人特化 / witcher specialization
- id: geralt
  agent:
    autonomous: true
    resources:                # ← NEW
      gold: 50
      potions: 2
  interact:
    cast_sign:   { resource: "mana", cost: 5, constraints: ["consumption"] }
    drink_potion:{ resource: "potion", constraints: ["consumption"], deltas: {"health": 20} }

3.2 Item Base + Specialization Item 基础 + 特化

# 苹果箱 — consumable item
- id: apple_crate
  zone: village
  interaction:
    private_attrs: { apple_count: 10 }
    interact:
      eat:     { resource: "apple", constraints: ["consumption"],
                  deltas: {"hunger": -10, "mood": 5} }
      open:    { reveal: true }
      pick_up: { resource: "apple", constraints: ["conservation"] }

# 魔法水晶 — special resource item
- id: magic_crystal
  interaction:
    private_attrs: { mana: 100 }
    interact:
      absorb:  { resource: "mana", constraints: ["conservation"] }
      shatter: { resource: "mana", constraints: ["consumption"], lose_all: true }
Extend rule 扩展规则: New entity → add 1 YAML block with interact: + resources:. NPC auto-inherits send/receive/talk/follow. Specialize by adding new keys to the entity's own interact:. Zero Python changes.

4. Constraint Registry 约束注册中心

Constraints are physical laws — not value judgments. The engine knows constraint names. The constraint classes know how to validate and apply. No domain knowledge (gold, mana, apple) exists in the engine core.

class ConservationConstraint:
    # 引擎不知道 gold, mana — 只知 resource 名字字符串

    def validate(self, agent, target, action_def, ledger) → bool:
        resource = action_def["resource"]
        amount   = action_def.get("amount", action_def.get("cost", 1))
        return ledger.balance(agent.id, resource) >= amount

    def apply(self, agent, target, action_def, ledger):
        resource = action_def["resource"]
        amount   = action_def.get("amount", action_def.get("cost", 1))
        ledger.transfer(agent.id, target.id, resource, amount)

5. Resource Ledger 资源账本

Flat entity-level balance sheet. Zero domain knowledge. Tracks what each entity holds. Transfers never create resources from nothing.

class ResourceLedger:
    # {entity_id: {resource_name: quantity}}
    _holdings: dict[str, dict[str, int]]

    def balance  (entity_id, resource) → int
    def all_of   (entity_id) → dict[str, int]
    def transfer (src_id, tgt_id, resource, amount) → bool
    def deposit  (entity_id, resource, amount)
    def withdraw (entity_id, resource, amount) → bool
Conservation law 守恒律: transfer(A,B,x,n) guarantees A.x -= n and B.x += n. If A's balance is insufficient, the entire operation returns False — no partial execution. Engine records every transfer via logger for audit trail.

8. Extension Guide 扩展指南

New Entity Type 新实体

1 file: world.yaml. Add entity block with interact: + initial resources:. NPCs auto-inherit base actions. Zero Python.

New Constraint 新约束

2 files: add class in constraints/ (30 lines), register via @register. Then YAML can reference it. Zero engine changes.

New Action 新动作

1 file: world.yaml. Add key to entity's interact: block. Define resource requirements, constraints, deltas. Zero code.

New Resource 新资源

1 file: world.yaml. Add to entity's resources: block. Reference in interact: actions. Zero code.

10. Design Philosophy 设计哲学对齐

Engine reports facts 引擎报事实

ResourceSource only reports balance. Engine never reports "you should save" or "this trade is worth it". Engine only reports gold: 45.

LLM provides cognition LLM 提供认知

LLM sees available actions + resource state through channels. Decides send, eat, talk, follow — all freely.

Constraints = Physical Laws 约束=物理定律

Conservation does not judge trades — only ensures no creation from void. Physical constraint, not economic opinion.

YAML is the extension surface YAML 是扩展面

New entity → add YAML. New action → add YAML key. New resource → add resources block. Zero Python.

Closed loop preserved 闭环保留

6 channels → LLM decide → interact execute → constraint apply → logger → next tick perception. Cycle unchanged.

Delete, don't add 删除不添加

Unified interact deletes NPC↔NPC vs NPC↔Item hardcoded branches. One dispatch by YAML action_type name.
